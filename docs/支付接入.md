# 支付接入（支付宝 / 微信支付）

充值链路：客户端 `POST /api/bill/order` → 服务端向渠道下单 → 客户端展示二维码或打开收银台 → 用户支付 → 渠道异步通知服务端 → 幂等入账 → 客户端轮询 `GET /api/bill/order/{orderNo}` 看到 `paid=true`。

服务端已实现真实渠道，凭据缺失时渠道不可用（下单返回 -906），**不会**静默退回模拟支付。渠道 9 为模拟支付，仅 `TestMode` 下可用，生产环境一律拒绝。

## 1. 渠道与产品对应

| 渠道 | 代码 | 支付产品 | 客户端表现 |
| :--- | :--- | :--- | :--- |
| 支付宝 | `channel=1`，`Mode=page`（默认） | 电脑网站支付 `alipay.trade.page.pay` | 自动打开浏览器收银台（`payUrl`） |
| 支付宝 | `channel=1`，`Mode=qr` | 订单码/当面付 `alipay.trade.precreate` | 打开服务端渲染的二维码页（`qrPngUrl`） |
| 微信 | `channel=2` | Native 支付（APIv3） | 同上，二维码内容为 `code_url` |
| 模拟 | `channel=9` | 无 | 仅本地测试 |

- 客户端默认走**支付组**：一次下单同时生成微信 + 支付宝两笔订单，详见 §8。
- 在线售卖软件建议签 **电脑网站支付**（需要可访问、通常已备案的网站）。
- 订单码支付需要经营场所/门店材料，更适合线下扫码场景；若已签约，把 `Mode` 改成 `qr`、`ProductCode` 改成 `QR_CODE_OFFLINE` 即可，代码无需再改。
- 微信 Native 需要已认证服务号/小程序/移动应用其中之一的 APPID，且商户号已开通 Native 并完成 APPID 绑定。

## 2. 服务端配置

`config.yaml`（不入库，模板见 `config.template.yaml`）：

```yaml
custom_config:
  ServerHost: "https://im.uesoft.com"   # 回调地址默认基于它拼
  Payment:
    Enabled: true
    Alipay:
      Enabled: true
      AppId: "2021..."
      Mode: "page"                      # page=电脑网站支付；qr=订单码/当面付
      ProductCode: ""                   # 留空自动：page=FAST_INSTANT_TRADE_PAY；qr=QR_CODE_OFFLINE
      PrivateKeyPath: "/etc/ueadmin/alipay_app_private.pem"
      PublicKeyPath: "/etc/ueadmin/alipay_public.pem"   # 支付宝公钥，不是应用公钥
      NotifyUrl: ""                     # 留空 = ServerHost + /api/bill/notify/alipay
    WeChat:
      Enabled: true
      MchId: "16..."
      AppId: "wxa..."                   # 与商户号绑定的已认证服务号/小程序/移动应用
      SerialNo: "商户API证书序列号"
      PrivateKeyPath: "/etc/ueadmin/apiclient_key.pem"
      ApiV3Key: "32位APIv3密钥"
      PublicKeyId: "PUB_KEY_ID_..."
      PublicKeyPath: "/etc/ueadmin/wechat_pub_key.pem"
      NotifyUrl: ""                     # 留空 = ServerHost + /api/bill/notify/wechat
```

- 私钥/公钥既可给文件路径（`*Path`），也可直接填 PEM（`*Pem`）；控制台复制的纯 Base64 会自动补 PEM 头尾。
- 支付宝签名固定 RSA2（SHA256withRSA）；微信固定 APIv3 + 微信支付公钥模式（不支持平台证书模式）。
- 密钥文件权限建议 `0600`，不要提交到任何仓库。

## 3. 回调地址

| 渠道 | 地址 |
| :--- | :--- |
| 支付宝 | `https://<ServerHost>/api/bill/notify/alipay` |
| 微信 | `https://<ServerHost>/api/bill/notify/wechat` |

要求：公网可达、HTTPS、微信地址不能带查询参数。两个回调都不经过 `AuthFilter`，验签在服务端完成。

## 4. 联调步骤

1. 执行数据库迁移：`0011_payment_pay_url.sql`、`0012_payment_refund.sql`、`0013_payment_group.sql`（新增 `payment_order.pay_group`）。
2. 填配置，启动服务，日志出现 `[Payment] ... 就绪=是`。
3. 先小额真实验证：充值 1 分（`amountCents=1`）。
   - 支付宝沙箱：`Gateway` 填 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`，AppId/密钥用沙箱应用；本机联调时通知到不了 `127.0.0.1`，靠轮询时的主动查单结算。
   - 微信无沙箱，只能 1 分钱真实支付。
4. 验证点：
   - 下单返回 `orderNo`，支付宝 page 模式有 `payUrl`，微信有 `qrContent` 且 `qrPngUrl` 能打开二维码。
   - 支付后 `GET /api/bill/order/{orderNo}` 变 `paid=true`，余额增加。
   - 重复回调/重复查询不重复入账。
   - `payment_callback_log` 能看到原始通知与 `verified=true`。

## 5. 关键实现

- 下单：`services/BillService.cc` → `AlipayProvider` / `WechatPayProvider`；订单号 `BOyyyyMMddHHmmss+6位随机`。
- 结算：回调与主动查单共用 `SettleOrder`，校验「订单存在 / 渠道一致 / 金额一致 / 状态为待支付」后，用一条 CTE 完成置已支付、加余额、记流水；`update ... where status = 0` 保证并发幂等。
- 回调丢失兜底：客户端轮询 `GET /order/{orderNo}` 时，服务端对待支付订单主动向渠道查单（同一订单 4 秒最多一次）。
- 二维码：`/api/bill/qr/{orderNo}` 按订单的 `qr_content` 实时渲染 PNG（内置二维码编码器），模拟订单返回占位图。
- 支付宝收银台 URL 不落二维码字段，存 `payment_order.pay_url`。

## 6. 常见错误

| 现象 | 原因 |
| :--- | :--- |
| 下单 -906「支付渠道未配置」 | `Payment.Enabled` 或渠道 `Enabled=false`，或 AppId/私钥/公钥/APIv3 密钥缺失 |
| 支付宝返回 `isv.invalid-app-id` | APPID 与密钥不匹配，或应用与商家账号未绑定 |
| 支付宝返回 `ACQ.TRADE_NOT_EXIST` | 正常：用户还没扫码/付款，查单时会返回 |
| 微信 `SIGN_ERROR` | 商户私钥/证书序列号不匹配，或请求体被网关改写 |
| 微信 `APPID_MCHID_NOT_MATCH` | 商户号未关联该 APPID，或 AppId 填错 |
| 回调一直 `failure` / `FAIL` | 公钥填成了「应用公钥」、APIv3 密钥不对，或回调地址被网关改写 |
| 二维码扫不出 | 确认 `qrContent` 非空且 `qrPngUrl` 返回 `image/png`；微信 `code_url` 有效期 2 小时 |

## 7. 退款

用户端：账户中心 →「我的订单」→ 选中已支付订单 → 填写原因 → 申请退款。
管理端：「我的」→「退款管理」（仅超级管理员可见）→ 筛选/搜索 → 查看详情 → 通过 / 驳回 / 同步 / 回滚。

规则与状态：

- 仅订单本人可申请；订单已支付且未超过 365 天；**整单全额**退款；申请与审批时都要求当前余额 ≥ 订单金额。
- 同一订单同时只允许一条有效申请（待审核/退款中/已退款）；驳回或失败后可重新申请。
- 状态：`0 待审核` → `1 退款中` → `2 已退款`；`3 已驳回`；`4 退款失败`。

审批资金流：

1. 单条 SQL 先校验并扣减余额、写 `balance_txn`（type=3，负数），退款单置为「退款中」。余额不足则整条语句不生效，返回 `-911`。
2. 调用渠道退款：支付宝 `alipay.trade.refund`；微信 `/v3/refund/domestic/refunds`。
3. 渠道成功 → 已退款；渠道处理中 → 保持退款中，可点「同步」；渠道失败/关闭 → 自动把余额加回并记「退款失败冲正」流水，退款单置为失败（可重试）。
4. 「回滚」仅用于退款中且渠道无法确认的卡单：退回余额 + 标记失败。

管理接口（均要求 `AuthFilter` + `SuperAdminFilter`）：

| 接口 | 说明 |
| :--- | :--- |
| `GET /api/admin/refunds` | 列表，支持 `status`、`keyword`（订单号/退款单号/用户/邮箱）、分页 |
| `GET /api/admin/refunds/{id}` | 详情 |
| `POST /api/admin/refunds/{id}/approve` | 通过并退款，body `{remark}` |
| `POST /api/admin/refunds/{id}/reject` | 驳回，body `{remark}` |
| `POST /api/admin/refunds/{id}/sync` | 同步渠道退款结果 |
| `POST /api/admin/refunds/{id}/rollback` | 卡单手动回滚余额 |

## 8. 支付组（双通道）

客户端“账户中心 → 充值”默认走支付组：一次下单同时生成微信 Native 与支付宝两笔订单，界面并列展示两个入口，任一方支付成功即关闭另一笔。

| 接口 | 说明 |
| :--- | :--- |
| `POST /api/bill/order/group` | body `{amountCents, idemKey}`；返回 `groupNo / amountCents / expireAt / paid / status / orders[] / unavailable[]` |
| `GET /api/bill/order/group/{groupNo}` | 轮询支付组；`paid=true` 时返回 `balanceAfterCents` |

- `orders[]` 每项含 `channel`、`qrContent`、`qrPngBase64`（服务端渲染的二维码 PNG，客户端直接解码显示）、`payUrl`。
- 支付宝电脑网站支付只返回 `payUrl`，没有二维码；客户端显示“打开支付宝收银台”。要显示支付宝二维码需加签当面付（`Mode=qr`）。
- 渠道未配置时不出单，放进 `unavailable[]`（例如支付宝未签约），不影响另一个渠道。
- 首付即关单：结算成功后关闭同组另一笔；若关单时渠道已支付，则等它自身结算后自动生成一条“待审核”退款申请（`reason=同组重复支付，系统自动提交退款`），仍需超管审核。
- 服务端每 60 秒补偿一次：组内已有一笔支付、另一笔刚被关闭的订单会再次向渠道查单，防止异步通知丢失导致已付款未入账。
- 幂等：同一 `idemKey` 返回原支付组；组内订单的 `idem_key` 带 `:1` / `:2` 后缀，配合 `(user_id, idem_key)` 唯一索引。
- 支付宝关单返回 `ACQ.TRADE_NOT_EXIST` 视为成功（电脑网站支付在用户打开收银台前渠道无单）。

## 9. 安全约束

- 应用私钥、商户私钥、APIv3 密钥只允许出现在服务端配置/密钥文件中，禁止下发到客户端、禁止写日志。
- 支付结果以验签后的异步通知或主动查单为准；客户端上报的状态、金额一律不采信。
- 回调金额与订单金额不一致时拒绝入账并记录错误日志。
